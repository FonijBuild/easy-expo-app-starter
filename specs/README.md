# Specifications

Non-trivial work begins with a specification copied from `_template.md`.

## Lifecycle

1. Draft: problem, scope, flows, contracts, acceptance criteria, and open questions.
2. Review: resolve product/security/design decisions before broad implementation.
3. Implement: keep the spec current when decisions change.
4. Verify: map tests and manual checks to acceptance criteria.
5. Complete: record rollout notes and remaining follow-ups.

Specs are behavior contracts. They should not dictate incidental code structure unless architecture is part of the requirement.
